# 对话脉络 v0.8.0 · 请求规划与分片阅读

- 模型能力与用户成本预算分开：能力绑定实际服务地址和模型。模型列表有明确能力字段时读取；没有时需按服务商依据确认，不按模型名称猜测。未知能力阻止新整理请求。
- 每次完整请求核对输入、输出预留和安全余量；成本采用估算，另以保守字节计量检查模型上下文，非服务端精确 Token 计数。
- 单轮长正文、过长历史摘要及补读原文自动分片，携带重叠原文、角色、来源位置、累计记忆与本次补读问题。段落与代码边界优先，源内容完整保留。
- 分片记忆保留确认/否定、矛盾、指代和未解决问题；摘录校验到实际原文。必要时用更短目标分级阅读，不把生成摘要作为证据。
- 最终仍合并到原轮次，可按需回读本轮指定原文范围（最多2次），引用按原始全文验证。只发布完整且通过校验的新图。
- 每片保存检查点并继续后台调度，设置页显示分片进度；兼容进度可恢复。浏览器重启后仍需手动续做，不自动重发可能已计费的未保存请求。
- 固定开销无法容纳、未知能力、接口错误、超出既有补查次数或模型输出校验失败仍明确暂停；不宣称拆分后必然语义正确，也不无限调用。

使用：重新加载扩展、刷新 ChatGPT → 设置中获取模型列表并核对能力依据 → 保存 → 点击“抽取关系图”新建任务。旧配置没有能力字段，不能直接续做旧任务绕过检查。原有API Key无需重新填写，除非临时Key已随浏览器重启丢失。

验证：339项模拟检查、19个JavaScript脚本语法检查通过；真实Edge与付费API未实测。没有调用付费API，没有批量修改个人资料库，没有自动提交或推送GitHub。

参考：[OpenAI模型对象](https://developers.openai.com/api/reference/resources/models/methods/retrieve)、[Token计量说明](https://developers.openai.com/api/docs/guides/token-counting)。实际容量以所用服务商的能力声明为依据。
